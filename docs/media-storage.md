# إعداد تخزين الصور في السيرفر

يُخزّن التطبيق الصور الجديدة في مجلد دائم خارج ملفات الإصدار، ثم يقدّمها عبر
`/api/media/<uuid>.<ext>`. هذا مناسب لسيرفر واحد أو لخوادم تشترك في وحدة تخزين
دائمة واحدة.

## الإعداد الموصى به

1. أنشئ وحدة تخزين دائمة واربطها، مثلاً، بالمسار:

   ```text
   /var/lib/blog-engine/uploads
   ```

2. امنح مستخدم التطبيق صلاحية القراءة والكتابة على المجلد.

3. أضف متغير البيئة التالي إلى خدمة التطبيق:

   ```env
   UPLOAD_STORAGE_DIR=/var/lib/blog-engine/uploads
   ```

إذا لم يُضبط المتغير، يستخدم التطبيق `storage/uploads` داخل مجلد المشروع. هذا
مفيد محلياً فقط، ولا يُعد تخزيناً دائماً عندما تستبدل منصة الاستضافة ملفات
الإصدار عند كل نشر.

## حد الطلب عند الوكيل العكسي

يفرض التطبيق حداً قدره 5 MiB للصورة و6 MiB لطلب الرفع. يجب أيضاً فرض الحد عند
Nginx أو مزود الاستضافة حتى يُرفض الطلب الكبير قبل أن يصل إلى Node.js. مثال
Nginx:

```nginx
client_max_body_size 6m;
```

## الصور الخارجية

الوضع الافتراضي يمنع Next.js من جلب الصور من نطاقات خارجية. اسمح فقط بالنطاقات
الموثوقة، مفصولة بفواصل ومن دون wildcard:

```env
IMAGE_REMOTE_HOSTS=cdn.example.com,images.example.org
```

تُقبل الصور الخارجية عبر HTTPS فقط، كما تُعطّل إعادة التوجيه داخل محسّن الصور
حتى لا يعيد نطاق موثوق توجيه الطلب إلى وجهة غير مسموحة.

## التشغيل والنسخ الاحتياطي

- انسخ مجلد الصور الدائم احتياطياً مع قاعدة البيانات.
- لا تشارك المجلد مع مستخدمين أو خدمات لا تحتاج إلى الكتابة فيه.
- عند تشغيل أكثر من نسخة للتطبيق، استخدم وحدة تخزين مشتركة تدعم القراءة
  والكتابة من كل النسخ، أو انقل التخزين إلى خدمة S3 متوافقة.
- تبقى الصور القديمة في `public/uploads` قابلة للعرض والحذف، بينما تستخدم كل
  الرفعات الجديدة المسار الدائم.
